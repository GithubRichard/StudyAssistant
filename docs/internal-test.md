# 网页版 v1 内测说明

目标：在只有一台云服务器（IP+端口直连，无备案、无域名）的情况下，
让家长/孩子用浏览器完成「提交作业 → 批改 → 复习台账」的完整闭环。

## 一、准备（服务器上，3 步）

```bash
# 1. 复制配置
cp config.example.yaml config.yaml

# 2. 生成网页账号（一个账号 = 一个孩子，可重复执行添加多个）
python3 scripts/make_web_user.py --username kid1 --display-name 老大
# 按提示输入两次密码，把输出的片段粘贴到 config.yaml 的 web.users: 下面

# 3. 启动（内测建议先用前台模式看日志）
#    注意：app.main 只导出工厂函数，必须加 --factory
uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8000
```

若已用 Docker 跑着服务，**不要再手动启动**（会端口冲突）；直接访问容器提供的网页版即可：

```bash
docker compose ps
docker compose logs -f          # 看启动日志
```

访问：`http://服务器IP:8000/`

- HTTP 直连只建议在可信网络下内测；公网长期使用请配置 HTTPS（域名+反代，二期）。
- `config.yaml` 不进版本库，改完配置需重启服务。

### 独立核验模型（推荐配置）

题号复核和方向确认默认用批改主模型"自己查自己"，有漏检风险。
配一个不同的模型做"第二双眼睛"（如 glm-4v-flash，短输出任务够用）：

```yaml
llm:
  providers:
    glm:
      enabled: true   # 并确认 .env 里有 GLM_API_KEY

staged_grading:
  orientation_provider: "glm"      # 方向确认的视觉裁判
  number_verify_provider: "glm"    # 题号复核员
```

改完重启生效。注意：二次复查走 Hermes 网关的 `review_model`，不受这两个配置影响。

## 二、冒烟测试清单

1. 打开页面 → 应跳到登录页，标题为配置的 `web.title`。
2. 用错的密码登录 → 提示"用户名或密码不正确"（不区分用户名/密码错误）。
3. 用正确账号登录 → 进入「今日学习台」。
4. 学习页 → 拍作业：学科默认「自动识别（按试卷判断）」，传一张作业照片、提交 → 任务状态页轮询 → 自动跳批改结果页。
   - 学科由模型按试卷内容推断，任务状态页与结果页展示推断出的学科；也可手动改选具体学科。
   - 页面从上到下：统计（做错 / 存疑 / 答对）→ 错题与存疑题列表 → 返回任务历史；**答对的题不逐条展示**，只在统计里体现数量。
   - 任一错题点「我觉得判错了」→ 确认后按钮变"已标记异议"，台账状态不变。
   - **手机浏览器里逐张拍照**：连点两次「选取文件 → 拍照」，两张都应留在预览里（不覆盖），下方提示"已选 2 / 20 张"；
     点缩略图右上角 × 可移除单张，计数同步变化；重复选同一张会提示"这张已经加过了"；提交后上传张数与预览一致。
     补充材料页的「补充图片」行为相同。
   - 若任务停在「需要补充材料」（`waiting_input`）：页面**先展示已经产出的结果**（统计 + 错题/存疑题），
     补充材料卡片（待补充信息清单 + 补充说明 + 补充图片 + 提交按钮）在**页面最下方**；
     提交后回到「正在处理…」并继续轮询。结果尚未产出时才是「需要补充材料」单卡片形态。
5. 任务历史 → 状态为「失败」/「已中断」的任务下方有「删除」按钮，确认后删除任务及关联图片（成功任务不可删，防止误删错题台账数据）。
6. 学习页 → 生成训练：选"按知识点"填知识点 → 提交 → 任务完成后进做题页（一题一屏）。
   - 点「做错了」→ 提示"已记入复习台账"；做完后去复习页能看到这道题（待订正）。
7. 复习页 → 点一条错题 → 详情页点「记为已订正」→ 状态变"待复测"；再点「复测通过」→ 变"已通过"。
8. 我的页 → 改学科、设学期起始日期 → 保存成功；退出登录 → 回到登录页。
9. 部署后前端立即生效（防"改了没用"）：
   - 整页刷新（F5）后必定是最新前端。`curl -I http://<IP>:8000/web/app.js` 应看到
     `cache-control: no-cache, must-revalidate`，且仍带 `etag`；带 `If-None-Match` 再请求返回 **304**（不重复传正文）。
   - **常驻标签页**：保持一个已登录标签页不动（不刷新）→ 服务端改动 `web/` 任一文件 → 1 分钟内
     （或把标签页切回前台时）底部导航之上出现琥珀色提示条「页面已更新，刷新后生效」+「立即刷新」。
   - 点「立即刷新」后应拿到新版本；**输入不会被自动刷新冲掉**：提示条只提示、不自动 `location.reload()`，
     在补充材料卡片里填着补充说明、选好图片时，页面不会自己重载。
   - `curl http://<IP>:8000/api/web/meta` 应返回 `asset_version`（8 位十六进制）且响应头含 `cache-control: no-store`。

> 为什么需要这一条：`web/` 三个文件（`index.html` / `app.js` / `styles.css`）既没有版本号也没有指纹，
> 而网页版是单页应用——点底部 tab 只改 hash、不会重新请求脚本。于是只要标签页不整页刷新，
> 浏览器就一直跑加载时那份旧脚本，服务端改了前端也进不来，看起来就像"修了没用"。
> 现在的两道防线：`/web` 静态资源一律回源校验（`no-cache` + 保留 `ETag`/`Last-Modified`，未变仍是 304），
> 再加上 `/api/web/meta` 的 `asset_version` 版本探针兜底长驻标签页。

## 三、数据保留说明

- 错题台账按账号保留 **2 年**（`retention_days: 730`），超期错题及关联的订正/复测事件由每日定时任务自动清理。
- **任务记录、附件、GitHub 归档不受影响**，不会被清理。
- 如需调整保留期，改 `config.yaml` 的 `retention_days` 后重启。

## 四、周总结

- 每周日凌晨（上海时间 02:00 后）服务端自动按**账号 × 科目**生成上一完整自然周（周一~周日）的学习总结，存入 `weekly_summaries` 表。
- 内容：批改任务数、逐题统计（答对/答错/未作答/存疑）、正确率及环比上周、新增错题、订正/复测数、高频错因 TOP5、薄弱知识点 TOP5、待办快照。
- 网页「我的」→「📊 周总结」查看；支持切换周、手动重新生成。服务器周日宕机时，重启后会自动补生成（往回看 8 周，只生成有数据的周）。
- 口径细节：`uncertain` 不计入正确率分母；用户点「我觉得判错了」已撤回的不计入新增错题；空科目归为「未分类」。
- AI 归类分析：生成时大模型自动分析本周错题——按错误类型归类（2-5 类，每类含题号/共性/建议）、薄弱知识点总结、下周学习重点；费用计入每日费用。模型失败时不影响统计部分落库（页面显示"暂不可用"）。`config.yaml` 的 `weekly_summary.ai_analysis: false` 可关闭。
