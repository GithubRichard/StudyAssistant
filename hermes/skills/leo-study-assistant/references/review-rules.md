# 错题二次核查规范（服务端版）

适用于主流程完成首轮批改、且**存在已判错题**时。核查方（子代理或核查轮次）只做只读核查，只回传异议与建议。

## 0. 运行前提与失败边界

- 核查模型必须由运行环境显式配置。**原 IDE 配置中的模型名（如 `glm-5.3-flashx-ioa`）不是可直接使用的接口模型 ID**，未确认映射前一律视为不可用。
- 模型不可用、超时、返回不完整时：把 `review_summary.state` 记为 `failed` 或 `not_run`，说明受影响题目；可恢复故障最多追加重试一次。
- 不得用其他模型冒充指定核查模型，不得把「主流程自行复核」写成「已完成子代理核查」。

## 1. 谁进入核查

- 只核查主流程判为 `wrong` 的题。
- `uncertain`、`unanswered` 不进入核查，也不能为了凑数改判为错题。
- 没有已判错题时跳过，`review_summary.state = not_required`。

## 2. 传入的完整材料

- 题目标识、来源与页码题号、完整题干（含选项、图表、共用条件与跨页条件）。
- 学生原作答、参考作答、主流程的判定结论、解题步骤与错因分析。
- 可访问的原始图片或材料；只能依据文字转录核查时，必须说明范围仅限转录内容的逻辑与计算。
- 题量较大时按完整独立题组拆分，每道错题只送一次，保留共用条件，不递归分派。

## 3. 核查方职责

- 重点检查：是否误读原题或作答、是否遗漏条件、计算或推理是否有误、是否把合理答案误判为错、错因是否缺乏证据。
- 有异议的题逐项返回：题目标识与来源、主流程相关结论、具体异议、可核验依据、建议的修正方向、待核实信息。候选答案仅作为建议。
- 无异议的题只标注「未发现异议」，不重复整套解析，也不等同于证明原判定必然正确。
- **不做二选一、不作最终裁决、不覆盖主流程结论**；不使用「正确／错误」给学生重新定性。
- 只读：不修改文件、不执行命令或 Git、不再委派其他代理、不发送任何消息。

## 4. 主流程处理异议

- 按首轮错题清单核对覆盖情况，区分 `agreed` / `disagreed` / `unverified` / `unprocessed`，消除重复结果。
- 对异议回看原始材料独立验证，不按多数票或模型置信度裁决；在 `final_decision_basis` 写明复核依据。
- 证据不足时保留存疑，不把建议直接写成确认事实。
- 发现系统性识别问题时扩大复核范围；不把整卷首轮批改交给核查方。
- 核查状态与学生作答判定分别保存，不混为一类统计；重新核查不计为新的出错或复测事件，
  也不得因为「已复核」把 `remediation.state` 改成复测通过——只有真实作答才改变复测状态。
- 核查未完成（`failed` / `not_run`）时，在 `review_summary.note` 与 `missing_info` 中说明受影响题目，
  不得写成「已完成双重确认」。
